# ADR 0036: Separate generated evidence churn from source cleanliness

- Status: accepted
- Date: 2026-08-01
- Release: v4.8.8

## Context

The first automatic `main` delivery produced valid GitHub/Sigstore attestations
and deployed v4.8.7, but its promotion-receipt follower rejected the manifest
as dirty. Quality commands intentionally regenerate versioned reports before
the manifest is signed. Treating those declared outputs as source edits makes a
clean checkout fail closed for the wrong reason and hides the actual blocking
configuration: the human-controlled receipt key is absent.

## Decision

Source cleanliness continues to fail closed for code, configuration,
documentation, unknown outputs and renames. The allowlist now covers only the
declared files regenerated by this quality workflow: iteration manifests,
model/stress/closure reports, the two deterministic study projections and the
portable replication bundle. The evidence generator emits the unexpected path
list before signing, and a failed Git query remains an explicit
`<git-status-unavailable>` source change.

Receipt signing, OIDC ingestion and trust-lane promotion remain separate. This
change cannot create a receipt, supply a secret, or turn a pending lane green.
Git porcelain normalization removes trailing line endings only; it must retain
the leading status column on the first row.

## Consequences

- Expected deterministic report churn cannot make an otherwise clean CI
  manifest dirty.
- Any unexpected path remains visible and prevents promotion.
- The next `main` run can prove the cleanliness fix through its signed
  manifest, while the missing private key and governance identity remain an
  honest external-configuration boundary.
